# 组内知识库建设方案

> 面向：研究生课题组（10 人以内，无服务器）
> 目标：每人本地管理个人知识库 + 组内经验与踩坑分享交流
> 核心原则：**个人数据本地化（local-first），共享区零门槛（人人都能写）**

---

## 一、架构总览

```
┌─────────────────────────┐   主动分享    ┌──────────────────────────┐
│ 个人知识库 · Obsidian    │ ──────────> │ 共享区 · 飞书知识库       │
│ 每人本地 .md 文件        │ 经验贴/踩坑贴 │ 人人可写、可评、可搜索     │
│ 私密、零成本、零门槛     │              │ 组内所有人可见            │
└─────────────────────────┘              └──────────────────────────┘
```

### 分工规则（最简版，写在新人指南里）

| 内容类型 | 放哪里 |
|---|---|
| 文献阅读、毕设材料、个人草稿、**私人的经验/踩坑/学习过程** | **Obsidian（本地）** |
| 愿意分享的经验贴、踩坑贴、组内通用规范 | **飞书知识库（共享区）** |
| 不确定的 | 先放本地，成熟后再分享 |

> 避免双份维护：**要分享的内容直接写在飞书**，Obsidian 只放纯个人内容。
> 不要把同一篇笔记在两个地方各维护一份。

### 为什么这么选

| 约束条件 | 对应的选择 |
|---|---|
| 无服务器、无运维资源 | 排除自托管（Outline/Wiki.js），选免费 SaaS 做共享区 |
| 个人数据要本地化 | Obsidian 本地 Markdown，数据主权完整，毕设/草稿无忧 |
| 组员水平不确定 | 共享区选零门槛的飞书，人人会写才有内容沉淀 |
| 10 人以内小团队 | 飞书免费版（100 人内）完全够用 |
| 一台设备为主 | 个人库不需要同步方案，零维护 |

**成本：0 元。** 飞书免费版 + Obsidian 免费版，无服务器、无域名、无备案。

## 二、实施步骤

### 第 1 步：搭个人库（Obsidian）· 每人约 30 分钟（先做）

> **先做个人库**：让每个人先把文献、项目、经验/踩坑、学习过程在本地沉淀下来，
> 养成"记笔记"的习惯。共享区的内容源头在这里——个人库不扎实，共享区建起来也是空的。

1. 官网下载安装 Obsidian（免费；组员均为 Windows，直接下 Windows 版安装包即可）
2. 新建 Vault（库），建议放在文档目录，如 `D:\MyVault`
3. 基础设置：语言中文、自动保存、深色/浅色主题随意
4. 推荐目录结构（不强求，够用即可）：

```
📁 MyVault
├── 10-文献笔记      ← 论文阅读笔记
├── 20-经验         ← 自己的经验、心得、方法
├── 30-踩过的坑      ← 遇到的问题、踩坑、教训
└── 90-模板         ← 放三份空白范文（文献笔记/经验/踩坑）
```

> 初期先聚焦这三类（文献笔记 / 经验 / 踩坑），模板放 `90-模板`；
> 以后有需要再按需加 `项目笔记`、`学习`、`Inbox` 等分区，不用一开始全建。

5. 教大家 5 分钟上手：
   - 新建笔记：`Ctrl+N`
   - 插入图片：粘贴即可
   - 代码块：``` 三个反引号
   - 笔记互链：`[[笔记名]]`
   - 搜索：`Ctrl+Shift+F`（全文搜索）
6. **个人库为推荐项，不强制**——有人不习惯可以只用共享区，不设置任何门槛

### 第 2 步：搭共享区（飞书知识库）· 约 1 小时（后做）

> **后做共享区**：等大家个人库用起来了、手上攒了几条值得分享的内容，再开飞书。
> 这样共享区一上线就有"种子内容"，而不是空壳。

1. 创建飞书团队（或用导师/学院已有的团队，建一个子群即可）
2. 邀请组员加入（每人用自己的手机号/邮箱注册）
3. 创建知识库，采用以下目录结构：

```
📚 XX课题组知识库
├── 00-新人指南          ← 进组必读：组内规范、工具、常用链接
├── 01-经验分享          ← 自己做成的事、方法、心得（完整教程也放这里）
├── 02-踩坑记录          ← 遇到的问题 + 解决办法
├── 03-项目文档          ← 按课题/项目建子目录（可选，按需启用）
└── 04-组会与纪要        ← 组会安排、会议纪要（可选，按需启用）
```

4. 权限设置：**知识库对组内成员可见、可编辑**；私密草稿放个人"我的空间"，不放入知识库
5. 把 `00-新人指南` 写好（见第四节模板），新人进组直接看

### 第 3 步：定义"桥"（个人 → 共享区）· 5 分钟

写在新人指南里的一句话规则即可：

> **"想分享就写飞书，不想分享就写本地。"**
> 经验贴/踩坑贴直接创建在飞书知识库对应目录；个人笔记留在 Obsidian。

**提问怎么办**：日常问题直接在飞书群里问（零门槛、即时）。被反复问、或解答有价值的问题，
由提问者或解答者整理成经验贴/FAQ 沉淀进知识库——这是共享区内容的重要来源之一。

### 第 4 步：模板与规范 · 约 30 分钟

在飞书知识库建两个模板，**模板是知识库能不能沉淀内容的关键**：

#### 经验贴模板（`01-经验分享` 下建一篇示例）

```markdown
# 标题：一句话说清经验（如：跑通 XX 训练的最快路径）

- 作者：｜日期：｜适用场景：

## 背景（为什么写这篇）
## 做法（怎么做的，分步骤）
## 结果（效果如何，有无数据）
## 踩过的坑（最重要！前人踩坑后人跳过）
## 相关链接
```

#### 踩坑贴模板（`02-踩坑记录` 下建一篇示例）

```markdown
# 标题：一句话说清这个坑（如：装 CUDA 版 PyTorch 后 GPU 不可用）

- 作者：｜日期：｜环境/场景：

## 现象（发生了什么）
## 原因（为什么会这样）
## 解决办法（怎么解决的）
## 避免方法（下次怎么绕开）
## 相关链接
```

> 运营技巧：第一周你自己先写 2-3 篇高质量经验贴做示范，比任何动员都有效。

### 第 5 步：运营机制 · 持续

| 事项 | 频率 | 负责 |
|---|---|---|
| 新成员 onboarding | 进组时 | 你（发新人指南链接即可） |
| 答疑沉淀（群里反复被问的问题整理成 FAQ/经验贴） | 随时 | 提问者 / 解答者 |
| 整理共享区目录、归档过时内容 | 每学期 | 你 + 1 名同学轮值 |
| 鼓励分享（组会上提一句"这周有谁写了经验贴"） | 每周组会 | 导师/你 |
| 备份共享区 | 每学期 | 你（飞书知识库可整体导出，存一份到本地/网盘） |

## 三、备选演进路线（将来可选）

现状方案满足 95% 需求，以下为将来选项，**现在不用做**：

1. **共享区升级为静态网站**：若将来组里有服务器、或有人愿意维护 Git 仓库，可用
   Obsidian + Git + GitHub Pages / Cloudflare Pages 把教程发布成网页，阅读无需登录。
   （注意：GitHub Pages 国内访问不稳定，Gitee Pages 已基本停止服务，需评估）
2. **个人库多设备同步**：若有人需要手机/多设备看笔记，Obsidian 可选官方 Sync（付费）
   或第三方同步（坚果云等）。
3. **数据迁移**：所有内容均为 Markdown，任何时刻导出迁移都无痛，不存在平台锁定。

## 四、附：新人指南模板（00-新人指南 内容）

```markdown
# 欢迎加入 XX 课题组 👋

## 本组常用工具
| 工具 | 用途 | 地址 |
|---|---|---|
| 飞书 | 组内沟通 + 知识库 | （团队链接） |
| Obsidian（可选） | 个人笔记 | obsidian.md |
| ... | | |

## 知识库使用规则（3 条）
1. 经验贴/踩坑贴写进对应目录，用模板
2. 个人笔记留在自己本地，不用上传
3. 不确定的先用模板起个草稿，慢慢完善

## 新人 30 分钟上手
1. 加入飞书团队，点开本知识库
2. 看 01-经验分享 和 02-踩坑记录 各 1-2 篇
3. 用模板写一篇自己的经验贴（哪怕是"装好 XX 软件"）

## 常用链接
- 组会安排：
- 服务器/资源：
- 师兄师姐的联系方式（可选）：
```
